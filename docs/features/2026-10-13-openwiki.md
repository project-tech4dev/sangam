# OpenWiki for Sangam — plan

## Context

We just wrote `docs/ARCHITECTURE.md`, `docs/CHANGELOG.md` and nested `CLAUDE.md` pointers (branch
`docs/architecture-and-history`, worktree `~/Documents/sangam-docs`, not pushed). They let an agent learn the
system without reading the code. Their weakness is **freshness**: they are only true while every PR remembers to
edit them. OpenWiki (LangChain, MIT, v0.7.2, released 2026-07-01) fixes exactly that.

### The core idea

- An agent reads the repo **and its git history**. It writes a linked Markdown wiki under `openwiki/`: a quickstart, an
  architecture page per area, workflows, operations and testing.
- Every material statement is a **claim**, stored in `openwiki/.claims/*.json`. Each claim is pinned to exact source lines
  (`repo://backend/app/ingest/agent.py#L136-L153`) by a hash of those lines.
- `openwiki code --update` diffs `HEAD` against the commit it last documented. It re-checks only the claims whose
  evidence lines changed, and rewrites only the pages affected. If nothing changed, no model call is made.
- It adds an `<!-- OPENWIKI:START -->` block to `AGENTS.md` and `CLAUDE.md` pointing agents at `openwiki/quickstart.md`.
- A scheduled GitHub Action runs `--update` and opens a PR on branch `openwiki/update`. A person reviews and merges it.
- `openwiki/INSTRUCTIONS.md` is the one file you write. It sets scope and priorities, and OpenWiki never overwrites it.
- `.openwikiignore` keeps paths from ever being read.

### Gaps for Sangam, and how this plan closes each

| Gap | Concrete example | Fix |
|---|---|---|
| **GitHub Actions is blocked** | Deploy runs on 2026-10-10 and 10-12 failed in 4 s (org billing, per `.memory/STATE.md`) | `make wiki-update` runs locally today; the workflow is committed and starts working once billing is fixed |
| **Two sources of truth** | OpenWiki would write its own list of Import's 11 supervisor tools, beside ARCHITECTURE.md §4's list | Split roles (your choice): OpenWiki owns the generated *what*; ARCHITECTURE.md shrinks to the curated *why*: invariants, decisions, known regressions, and links into `openwiki/` |
| **Conflicting instructions** | OpenWiki's block says "do not preload the wiki; source is authoritative", while our CLAUDE.md says "read first" | Reword our "Read first" block so the two agree: the wiki is the first stop for an *unfamiliar* area, and source wins when they disagree |
| **It only sees code** | It would describe `lifespan.py` without `emit_raw_events`, but not know #178 made that a regression | `INSTRUCTIONS.md` tells it to read `docs/CHANGELOG.md` (especially "Not finished"), `docs/features/` and the git log. CHANGELOG stays hand-written |
| **What gets sent and published** | `docs/entities/*.md` are research briefs about real organisations; `.env` holds keys; the **repo is PUBLIC**, so the wiki is too | `.openwikiignore` excludes secrets, `.memory/`, `docs/entities/`, `seed/data/`, lockfiles and worktrees; telemetry off |
| **Wrong provider picked silently** | `.env` has `OPENAI_API_KEY` (for the graph), and OpenWiki picks OpenAI first when `OPENWIKI_PROVIDER` is unset | Always set `OPENWIKI_PROVIDER=anthropic` and `OPENWIKI_MODEL_ID=claude-sonnet-5-5` explicitly |
| **Cost unknown** | The first pass reads about 650 tracked files; there are no published cost figures | `OPENWIKI_PAGE_CONCURRENCY=2`; record the token use of the first run in the PR body; updates redo only changed pages |

### Decisions taken

- OpenWiki and the curated docs both stay, with split roles.
- Freshness: a `make` target now, plus the scheduled workflow.
- Model: Sonnet 5.5 via Anthropic.

## Plan: three stacked PRs, stopping for review after each

All three stack on `docs/architecture-and-history`. The work happens in that worktree, never the shared checkout. This plan is first
committed as `docs/features/2026-10-13-openwiki.md` on the branch. No new tests (none of this is app code).

### M1 — Configure OpenWiki and generate the first wiki (PR A)

Files:
- **`openwiki/INSTRUCTIONS.md`** (new, hand-written). The brief:
  - The product in two lines: Ask Sangam and Sangam Import/Scout, Funder Match, Media & Signals.
  - Pages wanted:
    - `quickstart`
    - one architecture page per area: Ask, Import, Funder Match, Media, data and migrations, auth/RLS, frontend, platform/deploy
    - workflows: one Ask turn; one Import turn through save, promote and undo; migrate; deploy by hand
    - operations: make targets, envs, Vercel/Supabase
    - testing: unit / integration / evals tiers
  - Ground rules to carry over from CLAUDE.md: the agent tool lists are pinned by tests, the catalog is a security allowlist, migrations are manual, nothing deploys automatically.
  - "Read `docs/CHANGELOG.md` and `docs/features/` for why things are the way they are. Report unfinished plans as unfinished; do not restate the changelog."
  - Treat `docs/INGEST.md` as partly stale (see its header).
- **`.openwikiignore`** (new): `.env*`, `.memory/`, `.claude/worktrees/`, `docs/entities/`, `seed/data/`,
  `**/node_modules/`, `*.lock`, `frontend/package-lock.json`, `backend/uv.lock`, `db/scripts/*.dump`.
- **`Makefile`**, a new `##@ Wiki` group, following the `evals` pattern of `set -a; . ./.env` (Makefile:171–174):
  - `wiki`: `npx -y openwiki@0.7.2 code --init --print`
  - `wiki-update`: `npx -y openwiki@0.7.2 code --update --print`
  - Both with `OPENWIKI_PROVIDER=anthropic OPENWIKI_MODEL_ID=claude-sonnet-5-5 OPENWIKI_TELEMETRY_DISABLED=1
    OPENWIKI_PAGE_CONCURRENCY=2`, and an `rm -f openwiki/.run.json` afterwards.
  - Needs Node ≥ 22.22 (local is v26.6).
- Run `make wiki`. Commit `openwiki/`, including `.claims/`, `.page-manifest.json` and `.last-update.json`, and the
  marker blocks it adds to `AGENTS.md` and `CLAUDE.md`.

**Exit gate:**
- Spot-check 15 claims against the code, at least two per area. These include: Import's 11 supervisor tools, `undo.LOGGED` = 19, the match-v2
  points, 48 migrations, `CallerPool` running as the caller, and the agents built on the first turn.
- Any wrong claim is fixed through `INSTRUCTIONS.md` plus `make wiki-update`, never by hand-editing a generated page.
- Record the run's token use and duration in the PR body. Stop for review.

**Exit gate:**
- Every link from ARCHITECTURE.md and the nested CLAUDE.md files resolves to an existing `openwiki/` page.

- Stop for review.

### M3 — The scheduled workflow (PR C)

- **`.github/workflows/openwiki-update.yml`**, from OpenWiki's `examples/openwiki-update.yml` with the actions pinned to the same SHAs:
  - Triggers: `workflow_dispatch` and a daily `cron: "30 0 * * *"` (06:00 IST). A clean day makes no model call.
  - `fetch-depth: 0`, so the diff can see the commit it last documented.
  - Env: `OPENWIKI_PROVIDER: anthropic`, `OPENWIKI_MODEL_ID: claude-sonnet-5-5`, `ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}`,
    `OPENWIKI_TELEMETRY_DISABLED: "1"`; no LangSmith.
  - `add-paths`: `openwiki`, `AGENTS.md`, `CLAUDE.md`, the workflow file. Branch `openwiki/update`. **No auto-merge.**
- **Your action:** add the `ANTHROPIC_API_KEY` repo secret, and fix Actions billing. The workflow is inert until both are done.
- CLAUDE.md "Deployment" notes that this is the one scheduled workflow, and that it only opens PRs.

**Exit gate:**
- `actionlint` (or `gh workflow view`) parses the file.
- Once billing is fixed, a manual `workflow_dispatch` opens a PR, or reports "no changes" on a clean tree.
- Stop.
