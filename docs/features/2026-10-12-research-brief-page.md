# Research brief: read it in the app, not as a raw .md

## Context

On a funder profile, "Research brief ↗" opens a one-hour signed Supabase URL to
`source-archive/entities/<slug>.md`, and the browser shows raw markdown:

- `<sub>` source lines and the `<!-- Generated by make client-docs -->` stamp appear as literal text.
- PDF-extracted rupee signs come out as backticks (`` `594 cr `934 cr ``), which markdown would turn into code spans.
- The same quote repeats once per place. Azim Premji's creche sentence appears 7 times, once for each state.

**Goal:** the button opens a Sangam page, `/registry/funders/<slug>/brief`, which shows the same brief as a readable document:
- the summary first;
- a section index on the side;
- each finding as a headline, its quote, and a source line with a confidence tag;
- repeated quotes folded into one finding.

**Scope:** frontend only. There is no new endpoint and no new storage. The profile response already carries `brief.url`, and the Next server can fetch it. This matches "keep features simple".

## Approach

### 1. Parse the brief (`frontend/features/registry/brief/parseBrief.ts`, new)

`backend/app/ingest/brief.py::entity_markdown` writes a fixed shape, so a small pure parser turns it into data:

```ts
type Finding = { headline: string; year?: string; basis?: string; evidence: string;
                 source: { name: string; url: string; confidence: string } };
type Brief = { name: string; researched: string; status: string; stopped?: string;
               summary: string; website?: string; goals: string[];
               sections: { title: string; findings: Finding[]; text?: string }[];
               notFound?: string; sources: string[] };
```

Line rules, matching `entity_markdown` lines 168–227:
- `# name`: the brief's name.
- `<!-- … -->`: dropped.
- `Researched … · status **x** · reason`: the status line.
- Text before the first `##`: the summary.
- `## title`: a new section.
- `- **headline** (year) _basis_`: a finding.
- `  > evidence`: that finding's quote, kept as plain text, so the backticks stay literal.
- `  <sub>name · url · confidence x</sub>`: the finding's source. Split on ` · `: the URL is the second-to-last part and the confidence the last.
- The three special sections ("What it set out to find", "Looked for, not found", "Sources read") are read as goals, a missing-list text and a sources list.
- Any section the parser doesn't recognise keeps its raw lines as `text`. The page renders that text through ReactMarkdown with the safe settings `ScoutReply.tsx` already uses (`skipHtml`, `defaultUrlTransform`), so a future change to the brief's format degrades instead of breaking.

**Folding repeats:** findings in a section that share both the same evidence and the same source URL merge into one. Their headlines are joined, so the 7 creche rows read: "Bihar · Chhattisgarh · Jharkhand · Karnataka · Madhya Pradesh · Odisha · Rajasthan — Creches (FY2025-26)".

### 2. The page (`frontend/app/registry/funders/[slug]/brief/page.tsx`, new; a route file only)

The page is a server component:
1. Call `apiGet<FunderProfile>(/api/funders/${slug}/profile)`, the same call as the profile page.
2. If `brief` is null, return `notFound()`.
3. `fetch(brief.url, { cache: "no-store" })` and parse the text.
4. Render `<BriefArticle brief={…} funder={funder} rawUrl={brief.url} />`.

### 3. The article (`frontend/features/registry/brief/BriefArticle.tsx`, new)

- **Breadcrumbs:** Registry › Funders › *name* › Research brief, linking back to the profile.
- **Header:** the eyebrow "Research brief", an h1 with the name, then a meta row: researched date, a status `Tag` (`partial` uses the accent tone, `complete` accent-2), and the website.
- **Stopped reason:** shown as a muted note card, because it explains why the brief is partial (for example, "azimpremjifoundation.org returned HTTP 403 on every page").
- **Body:** a summary paragraph in `.reading .measure`. A funder summary's "TEN FIELDS: (1) … (10)" tail renders as a numbered list.
- **Sections:** an `h2` per section (anchored for `SectionIndex` from `frontend/components/ui/SectionIndex.tsx`), the index sticky beside the article as on `/resources`. Each finding is one row:
  - the headline in bold, followed by the year and a *derived* flag when there is one;
  - the quote as a `.brief-quote` (sage left rule, `--fs-sm`);
  - a source line: the source name linked to its URL (`target="_blank" rel="noopener noreferrer"`) plus a confidence `Tag` (high: accent-2, medium: neutral, low: outline).
- **Footer:** "What it set out to find" collapsed in a `<details>`, then "Looked for, not found", then "Sources read" as a link list. The final note ("Findings, not catalog rows…") closes the page. The header has a "Download PDF" button (the browser's print dialog, with print styles); there is no .md download.

### 4. The button (`frontend/app/registry/funders/[slug]/page.tsx`)

- `Research brief ↗` becomes `<Link href={/registry/funders/${slug}/brief}>Research brief →</Link>`, opening in the same tab.
- Both hero CTAs drop their inline `style` for a `.btn-ondark` class. The design system's `Button` already has an `ondark` variant (`rgba(255,255,255,0.16)`, white text). The page's outer `style` moves to a class too, as house rules require.

### 5. Styles

- **`globals.css`:** a new `/* --- Research brief --- */` block with `.brief`, `.brief-head`, `.brief-meta`, `.brief-section`, `.brief-finding`, `.brief-quote`, `.brief-source`, `.brief-foot`, plus `.btn-ondark`. Only existing tokens: `--fs-*`, `--radius-row`, `--color-accent-2-*`, `--color-divider`.
- **Design system:** mirror them in "Sangam Design System v2" `tokens/registry.css` (from #175) in the same PR, and add `.btn-ondark` to match `Button` ondark. The brief page is not a UI-kit screen, so no `ui_kits` file changes. `docs/DESIGN_SYSTEM.md`'s `registry.css` row gains "and the research brief".

### Not in this change

- **CSO briefs:** `save_research` publishes these too, but `OrgProfile` has no `brief` and there's no `/orgs/{slug}/brief` route. That's a backend follow-up.
- **The source file:** no `brief.py` change, so no brief needs republishing.

## Verification

1. `cd frontend && npm run lint && npm run build`.
2. Run `make up` (local stack), or `make dev-frontend` with `AGENT_URL=https://sangam-backend-one.vercel.app/agent`, then open `/registry/funders/azim-premji-foundation/brief`:
   - the stamp and `<sub>` tags don't show as text;
   - the 7 creche rows fold into one;
   - `` `594 cr `` shows literally rather than as code;
   - source links open in a new tab;
   - "Download PDF" saves the brief alone, in one column.
3. Open a funder with no brief: the profile shows no button, and `/brief` returns 404.
4. Check the page at 390 px width: the section index hides and nothing scrolls horizontally.
5. Open a PR. After merge, deploy the frontend only.
