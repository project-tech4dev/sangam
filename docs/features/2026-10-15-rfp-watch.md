# RFP Watch: open calls that fit an NGO, before the deadline

Draft v1, for review before any code. Three stacked PRs follow once the approach is agreed.

## Why
An NGO wants to hear about open calls for proposals that fit it, while there is still time to apply.

Most of the plumbing is already in place:
- **Tables:** `rfps`, `rfp_tags`, `rfp_locations`, and `rfp_matches` (with `week_of` and RLS).
- **Routes:** the `/rfps` router.
- **Screen:** an empty RFP Watch view in the Ask sidebar (`features/ask/views/RfpWatchView.tsx`).

What's missing is supply and a feed:
- **No supply.** Locally there are 99 calls, only 3 have a deadline, and none of them is still open. A call only
  arrives when Import happens to research its funder.
- **No matches.** `rfp_matches` is empty.
- **No screen.** The view shows "No calls tracked yet".

## How others solve this
| Approach | Who | Fit for Sangam |
|---|---|---|
| Editors type up calls from funder sites, newsletters and portals | FundsforNGOs, NGOBox, CSRBox, GrantStation | Their listings are the product: NGOBox blocks bots. Only with a partnership |
| Ingest structured government feeds | Grants.gov extract, EU Funding & Tenders API, GeM/CPPP | Indian CSR has no such feed; GeM is mostly procurement |
| Prospect on past giving, with open calls as a second tab | Instrumentl, Candid FDO | **Already built** as Funder Match. Most CSR money moves by invitation, not open calls |
| Watch known funder pages for changes | Visualping/Distill on 30–100 "apply" pages, a person reads each change | **This plan**, with a model reading the page instead of a person |
| Parse a shared inbox of funder newsletters | development teams | Best next source: many Indian calls go out only by email |
| NGOs paste a call link they received | community platforms | Cheap later step that reuses this plan's extractor |

What they all do once the calls exist:
- **Hard filters first.** Eligibility, place and a deadline still ahead are applied before any ranking.
- **Plain "why it fits" lines** on each call.
- **A tracker for saved calls,** which is what brings people back.

## Decisions
- **Who it's for:** the NGO, self-serve. It's not a staff curation queue.
- **Who can Save or mark "Not for us":** the org's members and admins. Stewards and other roles only read. This is
  the RLS `rfp_matches` already has (`0027_rls.sql`), so no policy changes.
- **Where calls come from:** funders Sangam already knows, in a one-time pull that staff run. There is no schedule
  and no cron.
- **How they're pulled:** a fixed pipeline, not an agent. The same steps apply to every funder, so an agent would
  mostly relearn them each time.
- **What counts as a call:** a title and a deadline in the future. Rolling, apply-anytime programmes are left out of
  v1, as `funder-intake-research` §8 already rules.
- **Who sees a call:** an org sees a call only when they share a high-level theme, meaning one of the taxonomy's
  domains: Education, Health, Livelihoods, Environment.
  - It's one SQL join with no score and no model.
  - An org's tags and a call's tags both roll up to their domain.
  - The feed is sorted by deadline.
  - match-v2 (geography, band, eligibility) is not used for calls in v1.
- **Pitch:** it isn't on master yet, so a card offers "Ask about this call" for now.

**Not in v1:**
- funders Sangam doesn't know;
- NGOBox and GeM;
- a schedule, or detecting changes between pulls;
- an email or WhatsApp digest;
- the hand-off to Pitch;
- citing a call in Ask (there is no `[rfp:N]` marker).

## The pull
```
make calls-pull [FUNDER=slug] [CONFIRM=1]

for each funder:
  1. FIND     candidates = pages Import cited for it + funders.website + one Tavily search on its domain
              Haiku picks the one page listing open calls, or none        → funders.calls_url
  2. READ     check_url (robots, source rules) + fetch_url                → plain text
  3. EXTRACT  Haiku, structured output → [{title, deadline, amount_min/max, states, themes, eligibility, url}]
              themes are picked from the fixed taxonomy list (5 domains, 11 themes), never free text
  4. WRITE    writer.write_rfp (existing: dedupes on funder+title+deadline, full provenance)
then once:
  5. CLOSE    open calls whose deadline has passed → closed
  6. MATCH    one INSERT … SELECT: each org with members × each open call sharing a domain → rfp_matches
  7. REPORT   funders with no page found, calls written, orgs per call, orgs with no theme (see nothing)
```

**Example.** For HDFC Bank, the candidates are two pages:
- `…/csr/parivartan`, which Import cited;
- `…/csr/apply-for-grant`, which Tavily found.

1. Haiku picks `apply-for-grant`.
2. That page says: "Call for Proposals 2026–27: skill development, Assam and Bihar, ₹25L–1Cr, last date 30 Nov 2026".
3. This becomes one `rfps` row, with its places and theme.
4. The call is tagged with the theme "Skilling for jobs & employment", which rolls up to the Livelihoods domain.
   Every member org tagged with Livelihoods, or with any theme under it, sees the call. An Education-only org does
   not.

**Cost:** about 61 Tavily searches plus about 120 Haiku calls per full pull.

## Milestones
### M1: supply, the one-time pull
- **Migration `0048_rfp_watch.sql`:**
  - `funders.calls_url` and `calls_url_found_at`. A funder that already has a page keeps it, so staff can correct a
    wrong pick.
  - `rfp_matches.status` gains `saved`.
  - The new columns go into the SQL catalog.
- **`backend/app/ingest/calls/`**, modelled on `ingest/news/`:
  - `find.py` finds the calls page.
  - `extract.py` reads the calls off the page, with its prompt in `calls/prompts/extract.md`.
  - Themes are resolved to `tags` ids by slug and written to `rfp_tags`. Today the only tags on `rfp_tags` are 3
    `csr_sector` tags, so nothing currently links a call to a domain.
  - `pull.py` runs the pull.
  - `run.py` is the CLI behind `make calls-pull`. A run over every funder needs `CONFIRM=1`.
- **Page reads use `check_url` and `fetch_url`.** `check_url` lets through a host that isn't in the registry when
  robots.txt allows it. They avoid `_read_page`, which archives to the global Supabase bucket as a side effect.
- **Exit gate**, on staging:
  - a page is found for most of the 61 funders, and the misses are listed;
  - N open calls with future deadlines, all with provenance;
  - 5 calls checked by hand against their pages.

### M2: matching and the feed API
- **`repositories/rfps.py::flag_matches`**, run at the end of the pull and also available as `make calls-match`:
  - A single `INSERT … SELECT … ON CONFLICT DO NOTHING` into `rfp_matches`, with `matched_by = 'rules:domain'` and
    `week_of`.
  - Org and call tags reach their domain through `tags.parent_id`, a recursive CTE up to `kind = 'domain'`.
  - Rows are written up front so that Save and dismiss can use the existing UPDATE-only RLS. `DO NOTHING` means a
    re-run never touches `status`.
- **`GET /rfps/feed?org=<slug>`**, running as the caller under RLS:
  - open calls with future deadlines, sorted by deadline;
  - each call with the domain and themes it shares with the org, e.g. "Livelihoods · Skilling for jobs";
  - saved calls whatever their status, so a closed call shows a badge instead of vanishing.
- **`PATCH /rfps/{id}/matches/{org_id}`** accepts `saved`.
- **Exit gate:**
  - matches for at least one real member org on staging;
  - for 5 calls, the orgs that see each one are checked by hand against their themes;
  - a call stays saved after a re-run.

### M3: the screen
- **`RfpWatchView`**, rebuilt on `ListPage`:
  - **Org picker:** `useOrgChoices`.
  - **Buckets:** For you · Closing in 30 days · Saved.
  - **Search:** the title and the funder.
  - **Filter:** one, by theme.
- **A card shows:**
  - the title and the funder;
  - the deadline and the days left, flagged at 14 days or fewer;
  - the band in ₹;
  - the shared theme, e.g. "Livelihoods · Skilling for jobs";
  - a "Read the call" link.
- **A card's buttons:** Save, Not for us, and "Ask about this call" (which seeds a new Ask chat).
- **Styles:** `.rfp-*` classes, with no inline styles, and a design-system sync of the Ask page in the same PR.
- **Exit gate:**
  - a browser test as a member, a steward and staff, and at phone width;
  - `npm run build` and `npm run lint` are green.

## For the reviewer
- **Domain or theme?** Domain-level matching is broad: an Education org sees every Education call, school quality
  and early years alike. Matching on the 11 themes would be narrower, but Environment and Others have no themes
  underneath them.
- **Orgs with no theme tags see nothing.** Locally only 48 of 654 orgs have a theme tag. Should the empty state ask
  the org to add its themes?
- **Should a feed with no matches point to Funder Match?** For example: "No open calls fit you; these 5 funders do."
  Most CSR money never goes through an open call.
- **Should rolling calls come in?** These are programmes that accept applications year-round. Including them means
  more supply, but makes it harder to tell a real open call from a programme page.
- **One calls page per funder enough?** Some PSUs post each call as its own PDF notice.
- **Which next source?** Either a shared inbox for funder newsletters, or a box where an NGO pastes a link.
