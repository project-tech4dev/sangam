# Coverage to 75%, backend and frontend

## Context
Codecov gates a PR at 70% of the lines it changes (backend only; the frontend's is informational) and lets
project coverage fall by at most 1%. Measured on master `f248e25`:

| | covered | size | gap to 75% |
|---|---|---|---|
| Backend, unit + integration merged (branch coverage on) | 60% | 15,141 statements, 4,256 branches | ~2,900 statements+branches |
| Frontend (v8, every file in `lib/ features/ components/`) | 1% | 3,139 lines, 153 files, 97 of them `.tsx` | ~2,330 lines |

The backend gap is almost all Sangam Import: `promote.py` (580 missed), `writer.py` (401),
`staff_sources.py` (326), `news/pipeline.py` (245), `ingest/tools/*` (~520), `calls/pull.py` (175, 0%).
The frontend has no DOM environment, so no component can be tested yet.

Decisions (2026-10-21): 75% is a **patch** gate from the first PR; the **project** target becomes 75% on
each side once tests get it there. Backend first, then frontend. One PR per milestone, stacked, review
between each.

Rules held throughout:
- No `omit`/`exclude` to lift the figure: every source file counts, as #267 set it up.
- Integration tests use the rolled-back `db` fixture and create their own rows. CI's Postgres is fresh;
  a test that leans on seeded or locally-imported rows fails there. (Three tests already do locally:
  `test_locations_seed` ×2 and `test_v2_content_present` see 952 districts where a fresh seed has 784.)
- Unit tests monkeypatch `repositories/` functions, never the pool, and assert agent tools return
  `"<tool> failed: …"` rather than raise.

## M0: the bar (PR 1)
- `codecov.yml`: backend patch target 70 → 75. Frontend patch 70 → 75, still informational until M3
  gives it a way to test a component (otherwise a one-line `.tsx` fix could not pass).
- CLAUDE.md and CONTRIBUTING.md say 75%; a CHANGELOG line.

Exit: a PR touching backend code shows `codecov/patch` against 75%.

## M1: Import's write path, integration tier (PR 2)
`promote.py`, `writer.py`, `matcher.py`, `undo.py`, `reshelve.py`, `repositories/matching.py`: hand-written
SQL the unit tier cannot reach. Each test builds the rows it needs in a rolled-back transaction, then
asserts what landed. Example: promote one researched funder whose name matches an existing row, assert it
merged into that row with provenance columns filled and no twin was created.

Exit: those six modules above 75%; backend merged figure reported in the PR.

## M2: Import tools and pipelines, unit tier (PR 3)
`ingest/tools/{pipeline,catalog,research}_tools.py`, `staff_sources.py`, `news/pipeline.py`, `news/store.py`,
`calls/pull.py`, `manual_checks.py`, `access.py`, `contract.py`, and the `proposals/tools/*`. Fakes for
the web search, page reader and model; repositories monkeypatched. Example: `save_research` with a field
that has neither a finding nor a gap returns the refusal string and writes nothing.

Exit: backend merged ≥ 75%; the backend **project** target in `codecov.yml` set to 75%.

## M3: frontend test setup and pure modules (PR 4)
- `jsdom` + `@testing-library/react`; Vitest takes `*.test.tsx`; shared mocks for `next/navigation`,
  `next/link`, CopilotKit hooks and the Supabase client in one setup file.
- Tests for `lib/`, `features/*/lib/` (toolLabels, citations, board, sourcePick, …) and the
  `components/ui/` primitives (ListPage's BucketCards, FilterRow, SearchBox, ListMore).
- Frontend patch gate made blocking at 75%.

Exit: frontend figure reported; patch gate enforced.

## M4+: frontend screens (PR 5, split further if large)
Registry list and profiles, Funder Match, Proposals, Media & Signals, Import cards, Ask sidebar and message
rendering: render with fixture data, assert what a user sees and what a click sends. Example: Registry with
a `?sector=` filter renders only matching rows and the filter chip shows dark sage.

Exit: frontend ≥ 75%; frontend **project** target set to 75%.
