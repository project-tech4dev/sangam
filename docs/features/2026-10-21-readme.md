# A README that reads like an open-source project

## Context
The README was written for the people building Sangam: 449 lines, 13 badges (7 of them the tech stack),
no picture of the product, and maintainer detail (why the ports are 5433/8010, which targets honour `ENV`,
the eval flag's reasoning) ahead of what the product does. Several facts are stale: it says the backend has
no authentication, that the catalog has 32 tables (37) and migrations run to 0019 (0047), and it names only
Ask and Import. GitHub's community profile scores the repo 25%: no CONTRIBUTING, code of conduct,
security policy or templates, and no description or topics.

What the projects we compared do (Langfuse, Supabase, Cal.com, Twenty, PostHog, Dify, Glific):
- a logo or banner and a screenshot in the first screen;
- a few badges that carry meaning, the stack in one "Built with" line;
- features described by what a user gets, each with a picture;
- a short README that links out; setup detail lives in CONTRIBUTING and docs;
- community files, and a stated owner and audience.

Decisions: link the live app (signed out it is a public preview); screenshots come from a local seeded
stack; security reports go to GitHub's private vulnerability reporting, which is already on.

Three stacked PRs on #267 (`chore/license-and-coverage`).

## M1: community files (PR 1)
- `CONTRIBUTING.md`: setup, everyday commands, tests, conventions, and how a PR is reviewed; it takes the
  maintainer material the README drops.
- `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1) and `SECURITY.md` (private reporting, scope, what we
  consider in scope: the SQL agent's guards, RLS, egress).
- `.github/ISSUE_TEMPLATE/` (bug, feature, config linking security) and `.github/pull_request_template.md`
  with the repo's checklist: tests, `make wiki-update`, ARCHITECTURE/CHANGELOG, design system.
- Repo description, topics and homepage.

Exit: GitHub's community profile at 100%.

## M2: README rewrite (PR 2)
Order: centred title, tagline and links (Live app · Docs · Contributing · Report a bug); four badges (CI,
backend and frontend coverage, license); hero image; Why Sangam; Features (Registry, Ask, Funder Match,
Pitch, Scout, Media & Signals, RFP Watch); How it works (the diagram and the two rules); Quickstart; Built
with; Documentation; Status; Contributing; License and "Built by Project Tech4Dev".

Exit: about 150–200 lines, every number matches the code, nothing removed that is not now in
CONTRIBUTING.md or `docs/`.

## M3: screenshots (PR 3)
Ask with citations, a Registry profile, Funder Match and Scout, from a local seeded stack, in
`docs/assets/readme/`, placed in the hero and Features.

Exit: the images render on GitHub in light and dark themes.
