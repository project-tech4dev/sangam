# Files

- [Ask Sangam](ask-sangam.md) - How the Ask agent is built. It has a fixed list of seven tools plus read-only skill readers, four on-demand skills, an ordered middleware stack and a four-layer SQL path (catalog, validator, executor, render) that runs as the signed-in caller under RLS. It also has a default-on answer audit, prompt rules and citation markers.
- [Auth, Roles and RLS](auth-roles-rls.md) - How Sangam authenticates callers (Supabase JWT or the dev user), maps them to roles (staff, org admin, member, steward), and enforces access with Postgres roles and RLS. Explains the caller pool versus the owner pool, which code runs on which, and who may write proposals.
- [Data and Migrations](data-and-migrations.md) - How Sangam's Postgres schema is organised by table group (including server-side proposals and document links), why a baseline plus forward-only migrations (latest 0048) define it, how the SQL catalog drift check gates backend boot, where documents live in storage buckets, and how provenance columns keep the optional Neo4j graph rebuildable.
- [Frontend](frontend.md) - How the Next.js app in frontend/ is laid out, how it reaches the backend (server-component REST versus the CopilotKit/AG-UI chat proxy), how the Ask workspace (sidebar, coming-soon gating, server-backed Proposals view), home page and navbar, Import/Scout and registry profile screens work, and the auth, caching and design rules that govern it.
- [Funder Match](funder-match.md) - How the in-code match-v2 rubric scores one organisation against funders with no model involved, covering profile loading, the seven criteria, tiers, saved runs and their RLS, the places it is consumed (compare_fit, REST, make match, the UI), and how a match card starts a proposal.
- [Media & Signals](media-and-signals.md) - How Sangam pulls news with Tavily, classifies each link per organisation, groups links into stories, applies visibility bars, optionally re-checks borderline matches with a verifier agent, stores the result, and serves it through REST routes, the Media & Signals view, Registry profiles and the Ask news-brief skill.
- [Platform](platform.md) - How the Sangam FastAPI backend is assembled, checked and run. Covers the app factory and routers, Settings and the model tiers, the lifespan with lazy agent loading, Langfuse tracing, the Vercel deploy topology, CI and the Dependency review check, Codecov thresholds, Makefile targets, the performance work behind it (including Ask's tool-result clearing and compare_fit sizing), and known regressions.
- [Proposal Copilot (Sangam Pitch)](proposal-copilot.md) - The third Sangam agent, on /proposal. Code owns the steps, exit checks, fact list, question rules, trace check, readiness, polish check and .docx versions, all stored in proposals.work (migration 0048). The model only proposes; code checks every write.
- [Sangam Import / Scout](sangam-import-scout.md) - How the Import agent (Scout on screen) is built. A supervisor and four isolated subagents research funders and NGOs. Findings merge into one published brief per organisation, and promote() moves the brief into the catalog through fixed-SQL writers with undo and human-in-the-loop pauses.
