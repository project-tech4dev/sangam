# Files

- [Ask Sangam](ask-sangam.md) - How the Ask agent is built. It has a fixed list of seven tools plus read-only skill readers, four on-demand skills, an ordered middleware stack and a four-layer SQL path (catalog, validator, executor, render). It also has an optional answer audit, prompt rules and citation markers.
- [Auth, Roles and RLS](auth-roles-rls.md) - How Sangam authenticates callers (Supabase JWT or the dev user), maps them to roles (staff, org admin, member, steward), and enforces access with Postgres roles and RLS. Explains the caller pool versus the owner pool and which code runs on which.
- [Data and Migrations](data-and-migrations.md) - How Sangam's Postgres schema is organised by table group, why a baseline plus forward-only migrations define it, how the SQL catalog drift check gates backend boot, where documents live in storage buckets, and how provenance columns keep the optional Neo4j graph rebuildable.
- [Frontend](frontend.md) - How the Next.js app in frontend/ is laid out, how it reaches the backend (server-component REST versus the CopilotKit/AG-UI chat proxy), how the Ask and Import/Scout screens work, and the auth, caching and design rules that govern it.
- [Funder Match](funder-match.md) - How the in-code match-v2 rubric scores one organisation against funders with no model involved, covering profile loading, the seven criteria, tiers, saved runs and their RLS, and the places it is consumed (compare_fit, REST, make match, the UI).
- [Media & Signals](media-and-signals.md) - How Sangam pulls news with Tavily, classifies each link per organisation, groups links into stories, applies visibility bars, optionally re-checks borderline matches with a verifier agent, stores the result, and serves it through REST routes, the Media & Signals view, Registry profiles and the Ask news-brief skill.
- [Platform](platform.md) - How the Sangam FastAPI backend is assembled and run. Covers the app factory and routers, Settings and the model tiers, the lifespan with lazy agent loading, Langfuse tracing, the Vercel deploy topology, the performance work behind it, and known regressions.
- [Sangam Import / Scout](sangam-import-scout.md) - How the Import agent (Scout on screen) is built. A supervisor and four isolated subagents research funders and NGOs. Findings merge into one published brief per organisation, and promote() moves the brief into the catalog through fixed-SQL writers with undo and human-in-the-loop pauses.
