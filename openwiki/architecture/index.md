# Files

- [Ask Sangam](ask-sangam.md) - How the Ask agent is built. It has a fixed list of six tools plus read-only skill readers, four on-demand skills, an ordered middleware stack (error backstop, retry limiter, model-call cap, compare_fit budget, tool-result clearing, fallback, cheap summarizer, optional audit) and a four-layer SQL path (catalog, validator, executor, render) that runs as the signed-in caller under RLS. The validator adds id and source columns so rows come back cited, and the prompt carries the catalog's table list. It also has a default-on answer audit, prompt rules and citation markers.
- [Auth, Roles and RLS](auth-roles-rls.md) - How Sangam authenticates callers (Supabase JWT or the dev user), maps them to roles (staff, org admin, member, steward), and enforces access with Postgres roles and RLS. Explains the caller pool versus the owner pool, which code runs on which, and who may write proposals.
- [Data and Migrations](data-and-migrations.md) - How Sangam's Postgres schema is organised by table group (including RFP Watch's rfps tables, server-side proposals and document links), why a baseline plus forward-only migrations (latest 0050, the proposal stage shift) define it, how the migration runner also owns LangGraph's checkpoint schema, how boot checks the SQL catalog and the checkpoint version, how shared public SQL fragments hide private sources, where documents live in storage buckets, and how provenance columns keep the optional Neo4j graph rebuildable.
- [Frontend](frontend.md) - How the Next.js app in frontend/ is laid out, how it reaches the backend (server-component REST versus the CopilotKit/AG-UI chat proxy), how screens live in the URL (?view=, ?thread=, ?proposal=, ?tab=, registry filters), how the Ask workspace (sidebar, the now-empty coming-soon gate, Funder Match, RFP Watch and the server-backed five-step Proposals view), home page and navbar, Import/Scout (role-gated tasks, approval cards) and registry screens work, and the auth, caching, testing and design rules that govern it.
- [Funder Match](funder-match.md) - How the in-code match-v2 rubric scores one organisation against funders with no model involved, covering profile loading, the seven criteria, tiers, saved runs and their RLS, the places it is consumed (compare_fit, REST, make match, the UI), and how a match card starts a proposal.
- [Media & Signals](media-and-signals.md) - How Sangam pulls news with Tavily, classifies each link per organisation, groups links into stories, applies visibility bars, optionally re-checks borderline matches with a verifier agent, stores the result, and serves it through REST routes, the Media & Signals view, Registry profiles and the Ask news-brief skill.
- [Platform](platform.md) - How the Sangam FastAPI backend is assembled, checked and run. Covers the app factory and routers, Settings and the model tiers, the shared DB pool and verify-only checkpointer, the egress guard, the lifespan with lazy agent loading, Langfuse tracing, the Vercel deploy topology, CI and the Dependency review check, Codecov thresholds, Makefile targets, the performance work behind it (including Ask's tool-result clearing and compare_fit sizing), and known regressions.
- [Proposal Copilot (Sangam Pitch)](proposal-copilot.md) - The third Sangam agent, on /proposal. Code owns the five steps, exit checks, fact list, question rules, trace check, readiness, public (secondary) research, polish check and .docx versions, all stored in proposals.work (migration 0048; 0050 inserted the "Make a case" step). The model only proposes; code checks every write.
- [RFP Watch (open calls)](rfp-watch.md) - How Sangam finds, reads and stores funders' open calls for proposals, matches them to organisations by shared theme domain, serves them through /rfps routes, shows them in the RFP Watch screen and starts the pull from Scout or the make targets.
- [Sangam Import / Scout](sangam-import-scout.md) - How the Import agent (Scout on screen) is built. A supervisor and four isolated subagents research funders and NGOs. Findings merge into one published brief per organisation, and promote() moves the brief into the catalog through fixed-SQL writers with undo and human-in-the-loop pauses.
